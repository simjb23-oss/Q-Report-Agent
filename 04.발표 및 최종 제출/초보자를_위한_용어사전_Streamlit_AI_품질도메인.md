## 1. 💻 소프트웨어 & 개발 기술 용어

### ① Streamlit (스트림릿)
* **쉽게 말하면:** 파이썬(Python) 코드 몇 줄로 예쁜 웹 사이트/대시보드를 뚝딱 만들어주는 도구.
* **왜 썼나요?:** 웹 개발(HTML, CSS, 자바스크립트, 백엔드 서버 등)을 복잡하게 다 만들려면 몇 주가 걸리지만, Streamlit을 쓰면 데이터 분석가나 AI 엔지니어가 파이썬만으로 단 하루 만에 전문가 수준의 반응형 웹 화면을 제작할 수 있기 때문입니다.
* **우리 프로젝트 역할:** 사용자가 PDF 성적서를 올리고, 판정 결과를 그래프로 보고, 버튼을 눌러 승인/메일 발송을 하는 **전체 웹 UI 화면**을 담당합니다.

### ② Plotly (플롯리)
* **쉽게 말하면:** 마우스를 올리면 숫자가 뜨고 확대/축소가 되는 살아 움직이는 대화형(인터랙티브) 차트 라이브러리.
* **우리 프로젝트 역할:** 단순한 정적 이미지가 아니라, 제품의 측정값(빨간 점/초록 점)이 기준치(규격 상하한선 점선) 안에 들어왔는지 마우스로 찍어보며 확인할 수 있는 **품질 산포도 & Cpk 정규분포 곡선 그래프**를 그려줍니다.

### ③ Session State (세션 상태)
* **쉽게 말하면:** 웹 브라우저를 새로고침하거나 버튼을 눌러도 이전에 분석했던 데이터나 로그인 정보가 날아가지 않고 메모리에 기억되도록 유지해주는 저장 주머니.
* **우리 프로젝트 역할:** 성적서를 분석한 후 '팀장 승인 버튼'이나 '메일 초안 생성 버튼'을 눌렀을 때, 화면이 초기화되지 않고 분석 결과가 그대로 유지되도록 합니다.

### ④ PyMuPDF / Fitz (파이뮤피디에프) & pypdf
* **쉽게 말하면:** 파이썬에서 PDF 문서를 고속으로 읽고 텍스트, 표, 좌표, 이미지를 뜯어내는(파싱하는) 전문 라이브러리.
* **우리 프로젝트 역할:** 협력사가 보낸 스캔/전자 PDF 성적서에서 검사 수치, 날짜, 모델명, 합격 여부 텍스트를 정확하게 추출합니다.

### ⑤ Regex (정규표현식 / Regular Expression)
* **쉽게 말하면:** 문서 안에서 특정 규칙이나 패턴(예: 전화번호 형태 `010-XXXX-XXXX`, 날짜 형태 `YYYY-MM-DD`, 소수점 숫자 `12.34mm`)을 번개처럼 찾아내는 문자열 검색 문법.
* **우리 프로젝트 역할:** 성적서 양식이 업체마다 달라도 '치수', '두께', '전압', '보고서 번호' 같은 핵심 데이터를 쏙쏙 뽑아냅니다.

## 2. 🤖 인공지능 & LLM 관련 용어

### ① AI Agent (인공지능 에이전트)
* **쉽게 말하면:** 단순히 질문에 답만 해주는 챗봇(Chatbot)을 넘어서, **스스로 생각(Thought)하고 적절한 도구(Tool)를 직접 실행(Action)하여 목표를 완수하는 능동적인 AI**.
* **우리 프로젝트 역할:** 
  1. PDF를 읽고 ➔ 2. 사내 도면 DB를 조회하고 ➔ 3. 공차를 계산하고 ➔ 4. 불합격이면 보고서(NCR)를 만들고 ➔ 5. 협력사에 보낼 다국어 이메일까지 작성하는 전 과정을 사람처럼 알아서 척척 수행합니다.

### ② LLM (Large Language Model / 거대언어모델)
* **쉽게 말하면:** 수천억 개의 문장을 학습하여 인간처럼 글을 이해하고 작성하는 초거대 인공지능 (예: ChatGPT, Google Gemini 등).
* **우리 프로젝트 역할:** Google Gemini API를 사용하여 해외 협력사(중국 여요시, 베트남 등)에 보낼 격식 있고 정중한 무역/품질 비즈니스 공문 이메일을 자동으로 번역 및 작문해 줍니다.

### ③ OCR (Optical Character Recognition / 광학 문자 인식)
* **쉽게 말하면:** 스캐너로 뜬 종이 문서나 이미지 사진 속에 적힌 글자를 컴퓨터가 읽을 수 있는 디지털 텍스트로 바꿔주는 기술.
* **우리 프로젝트 역할:** 협력업체 공장에서 도장을 찍어 종이로 스캔해 보낸 흐릿한 성적서에서도 정확하게 숫자를 읽어냅니다.

### ④ Rule-based Fallback (룰베이스 폴백 / 하이브리드 안전장치)
* **쉽게 말하면:** "인터넷이 끊기거나 AI API 키가 없어도 프로그램이 멈추지 않고, 컴퓨터에 내장된 수학 공식과 규칙(Rule)으로 100% 정상 작동하도록 만든 비상 플랜".
* **우리 프로젝트 역할:** 인터넷 연결이 없거나 Gemini API 호출이 실패해도, 사내 ISO 2859-1 수학 공식과 표준 템플릿 엔진으로 완벽하게 판정 및 보고서 출력을 완료합니다.

## 3. 🏭 제조 & 품질보증(QA/QC) 도메인 용어

### ① COA (Certificate of Analysis / 시험 성적서)
* **쉽게 말하면:** 제품이나 부품을 납품할 때 "우리가 검사해 보니 제품 규격에 맞게 잘 만들어졌습니다"라고 보증하는 **공식 품질 보증서**.
* **다른 이름:** 출하검사 성적서(OQC Report), 수입검사 성적서(IQC Report).

### ② 공차 (Tolerance) & LSL / USL
* **쉽게 말하면:** 기계로 부품을 깎을 때 0.001mm까지 완벽히 똑같을 순 없으므로, **"이 범위 안이면 정상 합격으로 쳐줄게!"라고 약속한 허용 오차 범위**.
  - **Nominal (기준치):** 설계 도면상 딱 맞는 이상적인 목표 크기 (예: 10.00mm).
  - **USL (Upper Specification Limit / 규격 상한선):** 허용 가능한 가장 큰 치수 (예: 10.20mm).
  - **LSL (Lower Specification Limit / 규격 하한선):** 허용 가능한 가장 작은 치수 (예: 9.80mm).
* **OOS (Out of Specification):** 이 허용 범위를 벗어난 **규격 이탈/불량**.

### ③ ISO 2859-1 & AQL (Acceptable Quality Limit / 합격품질한계)
* **쉽게 말하면:** "만 개를 납품받았을 때 만 개를 다 까서 볼 수 없으니(전수검사 불가), 통계적으로 몇 개만 뽑아서(샘플링 검사) 불량이 몇 개 이하일 때 전체를 합격으로 인정할 것인가?"를 정해놓은 **세계 공통 국제 표준 룰북**.
  - **Major (중결함):** 기능상 문제 (AQL 1.0 등 엄격).
  - **Minor (경결함):** 미세한 스크래치 등 (AQL 2.5).

### ④ NCR (Non-Conformance Report / 부적합 보고서)
* **쉽게 말하면:** "너희가 보낸 부품에서 심각한 불량이 발견되었으니, 입고를 보류하고 당장 해결책을 가져오라"고 공식 항의하는 **품질 불합격 통보 공문**.

### ⑤ 8D Report (8 Disciplines / 8D 대책 보고서)
* **쉽게 말하면:** 포드(Ford) 자동차에서 시작되어 전 세계 글로벌 제조 기업이 표준으로 쓰는 **불량 문제 해결 8단계 보고서**.
  - "왜 불량이 났는지 5번 질문(5-Why)하고, 당장 어떻게 격리할 것이며, 앞으로 평생 다시는 안 생기게 어떤 설비를 고칠 것인가?"를 작성해야 합니다.

### ⑥ Cpk (Process Capability Index / 공정능력지수)
* **쉽게 말하면:** "이 협력사 공장이 물건을 만들 때 불량 없이 얼마나 안정적이고 정밀하게 찍어내고 있는가?"를 나타내는 성적표 점수.
  - 보통 **Cpk 1.33 이상**이면 우수한 공장으로 인정받습니다.

## 4. 🎯 심사위원이 자주 묻는 질문(Q&A) 치트키

### Q1. "기존의 파이썬 판정 프로그램이랑 AI Agent는 뭐가 다른가요?"
> **답변 팁:**  
> "일반 프로그램은 사용자가 하나하나 버튼을 누르고 데이터를 맞춰줘야 하지만, 저희 **AI Agent는 자율성(Autonomy)**을 가집니다. 비정형 PDF 성적서를 넣으면 스스로 문서 유형을 인식하고, 사내 마스터 DB에서 도면 규격을 찾아 매핑하며, 불합격 시 표준 NCR 공문과 중국어/영어 이메일 초안까지 한 번에 알아서 생성해 주는 **엔드투엔드(End-to-End) 자율 워크플로우**를 완성했다는 점이 가장 큰 차별점입니다."

### Q2. "LLM이 가끔 헛소리(할루시네이션)를 하는데, 품질 검사에서 믿고 쓸 수 있나요?"
> **답변 팁:**  
> "아주 중요한 지적이십니다! 그래서 저희는 **'수치 판정'과 '문서 작성'을 철저히 분리**했습니다. 0.01mm의 공차 계산이나 ISO 샘플링 판정 같은 정밀 연산은 100% 신뢰할 수 있는 **결정론적 룰 엔진(Python Tolerance Engine)**에 맡기고, LLM은 복잡한 다국어 비즈니스 이메일 작문과 맥락 요약에만 한정하여 활용함으로써 **오판율 0%**를 달성했습니다."

### Q3. "Streamlit을 쓴 이유가 무엇인가요? 상용화 서비스로도 가능한가요?"
> **답변 팁:**  
> "현업 품질 엔지니어와 공장 검사원들이 복잡한 설치 없이 브라우저에서 직관적으로 Split-View(성적서 원본 대조)를 확인하고 원클릭 결재를 할 수 있도록 빠르고 완성도 높은 반응형 UI를 제공하기 위해 Streamlit을 도입했습니다. 백엔드 로직이 모듈화되어 있어 향후 사내 ERP나 사내 인트라넷 웹으로도 즉시 이식 가능합니다."
