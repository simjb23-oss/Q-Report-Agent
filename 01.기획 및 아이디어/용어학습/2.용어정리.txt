



AI 에이전트 & 공모전 핵심 용어 가이드 (비전공자 및 개발 입문자용)

이 문서는 AI와 소프트웨어 개발을 처음 접하는 분들이 공모전 참가 신청서를 작성하고 프로토타입을 구상할 때 마주치는 낯선 기술 용어를 쉽게 이해할 수 있도록 일상적 비유와 실무 예시를 더해 구성한 해설서입니다.

---

1. AI 및 에이전트 기본 원리

LLM (거대언어모델, Large Language Model)
- 비유: 백과사전을 통째로 외운 세상에서 가장 똑똑한 대학원생의 두뇌
- 상세 설명: ChatGPT, Claude, Gemini처럼 전 세계의 인터넷 글과 서적을 방대하게 읽고 학습하여, 사람의 말을 자연스럽게 이해하고 문맥에 맞는 문장을 작문해 내는 인공지능 모델 그 자체를 뜻합니다.
- 주의점: 지식은 풍부하지만 실시간 인터넷 정보나 우리 회사만의 내부 비밀 문서는 알지 못합니다.

AI Agent (AI 에이전트)
- 비유: 생각만 하는 것이 아니라 손발을 움직여 직접 심부름과 업무를 처리하는 유능한 전속 비서
- 상세 설명: 기존의 챗봇은 질문을 던지면 말로 대답하고 끝나지만, 에이전트는 사용자의 목적을 파악한 뒤 직접 외부 도구를 다룹니다. 예를 들어 자료 검색, 엑셀 표 정리, 계산기 두드리기, 이메일 전송까지 정해진 목표를 달성하기 위해 연속적인 행동을 알아서 수행합니다.

RAG (검색 증강 생성, Retrieval-Augmented Generation)
- 비유: 시험을 칠 때 기억에만 의존하지 않고, 책상 밑에 사내 업무 매뉴얼(오픈북)을 펼쳐 두고 컨닝하며 정확한 정답을 쓰는 기술
- 상세 설명: AI에게 사내 규정집, 과거 불량 보고서(PDF, 엑셀)를 미리 보관해 두었다가, 사용자가 질문하면 그 서류 더미에서 가장 관련된 문단을 먼저 찾아낸 뒤 그 내용을 토대로 답변을 작성하게 만드는 방식입니다.

환각 현상 (Hallucination, 할루시네이션)
- 비유: 모르는 질문을 받았을 때 당황하지 않고 천연덕스럽게 거짓말을 지어내는 현상
- 상세 설명: AI가 모르는 정보에 대해 그럴듯한 거짓 정보를 사실인 것처럼 꾸며내 대답하는 오류를 말합니다. RAG 기술을 사용하면 이 환각 현상을 획기적으로 줄일 수 있습니다.

Prompt (프롬프트)
- 비유: 비서에게 건네는 구체적인 업무 지시서 또는 가이드라인
- 상세 설명: AI가 최고의 성능을 내도록 입력창에 적는 질문, 배경 설명, 제약 조건, 출력 형식(예: 표 형태로 출력해 줘 등)을 모두 아우르는 말입니다. 지시가 구체적일수록 결과물의 퀄리티가 높아집니다.

---

2. 화면 제작 및 프로토타입 구현 용어

Python (파이썬)
- 비유: 전 세계 개발자와 AI 연구원들이 사용하는 가장 대중적인 만국 공통어
- 상세 설명: 컴퓨터에게 명령을 내리는 프로그래밍 언어 중 하나로, 문법 구조가 일상 영어와 가장 비슷하여 초보자가 배우기 쉽습니다. 현재 전 세계의 거의 모든 AI 라이브러리와 도구가 파이썬을 1순위로 지원합니다.

Streamlit (스트림릿)
- 비유: 복잡한 건축 공사 없이 파이썬 글자 몇 줄로 완성되는 조립식 모델하우스
- 상세 설명: 원래 인터넷 웹페이지를 만들려면 HTML, CSS, JavaScript 같은 전문 기술을 한참 배워야 합니다. 하지만 스트림릿을 쓰면 파이썬 코드 몇 줄만으로 검색창, 버튼, 파일 업로드창, 표, 차트가 달린 깔끔한 웹 화면을 30분 만에 구현해 줍니다. 공모전 데모 시연에 가장 적합한 도구입니다.

UI (유저 인터페이스, User Interface)
- 비유: 자판기 겉면에 달린 음료수 사진, 누르는 버튼, 동전 투입구의 생김새
- 상세 설명: 사용자가 프로그램을 다룰 때 눈으로 보고 손으로 누르는 모든 화면 요소(버튼, 입력창, 메뉴 바, 폰트 색상 등)를 뜻합니다.

UX (유저 익스피리언스, User Experience)
- 비유: 자판기 버튼을 누르고 음료수가 나오기까지 느끼는 편리함과 직관성
- 상세 설명: 사용자가 그 프로그램을 사용하면서 느끼는 전반적인 편리함, 흐름의 자연스러움, 만족도 등의 총체적인 경험을 말합니다.

프로토타입 (Prototype)
- 비유: 정식 출시 전 맛과 반응을 보기 위해 소량 구워낸 시식용 빵
- 상세 설명: 공모전에서 요구하는 결과물은 완성형 상용 소프트웨어가 아니라, 기획한 아이디어가 실제로 돌아간다는 것을 증명하는 시연용 견본 모델입니다. 핵심 기능 한두 가지만 확실하게 작동하면 높은 평가를 받습니다.

3. 데이터 통신 및 시스템 연동 용어

API (애플리케이션 프로그래밍 인터페이스)
- 비유: 식당 손님의 주문서를 주방 요리사에게 전달하고 음식을 날라주는 서빙 직원
- 상세 설명: 내 컴퓨터에 무겁고 거대한 AI 시스템을 직접 설치하지 않고도, 인터넷 연결선(API)을 통해 구글이나 오픈AI의 강력한 AI 두뇌를 호출하여 결과를 받아올 수 있도록 해주는 통신 창구입니다.

API Key (API 키)
- 비유: 식당에 들어갈 때 보여주는 개인 전용 회원권 또는 신용카드 번호
- 상세 설명: 외부 AI 서비스를 사용할 때 내가 정당한 권한을 가진 사용자임을 인증하는 고유한 비밀 암호 문자열입니다. 외부에 유출되지 않도록 주의해야 합니다.

CSV / JSON (데이터 규격)
- 비유: 컴퓨터가 한눈에 읽기 편하게 반듯하게 줄을 그어둔 표준 장부 서식
- 상세 설명: 
  CSV는 엑셀 표의 각 칸을 쉼표로 단순하게 구분해 둔 텍스트 형식입니다.
  JSON은 컴퓨터 프로그램끼리 데이터를 주고받을 때 데이터의 이름표와 값을 짝지어 정리해 둔 표준 규격입니다.

오케스트레이션 (Orchestration)
- 비유: 여러 악기가 제 박자에 맞춰 화음을 내도록 지휘하는 오케스트라 지휘자
- 상세 설명: AI 모델 하나만 쓰는 것이 아니라 문서 검색기, 계산 모듈, 요약 에이전트, 파일 변환기 등 여러 개의 작은 도구들이 서로 엉키지 않고 정해진 순서대로 작동하도록 전체 작업 흐름을 제어하는 기술입니다.

4. 공모전 서류 및 심사위원 평가용 실전 표현

페인 포인트 (Pain Point)
- 뜻: 현장 작업자나 실무자가 매일 겪는 가장 답답하고 고통스러운 문제점
- 활용: 우리 프로그램이 멋지다는 말보다, 실무자가 어떤 고통(예: 수기 문서 찾는 데 3시간 낭비)을 겪고 있었는지를 먼저 짚어주어야 심사위원이 공감합니다.

엔드투엔드 (End-to-End)
- 뜻: 처음부터 끝까지 사람의 개입 없이 한 번에 자동 처리되는 완결형 구조
- 활용: 데이터 입력부터 최종 보고서 파일 생성까지 전 과정이 매끄럽게 하나로 이어질 때 엔드투엔드 자동화 워크플로우를 구현했다고 표현합니다.

도메인 특화 (Domain-Specific)
- 뜻: 일반적인 두루뭉술한 내용이 아니라 특정 전문 산업 현장에 딱 맞춘 상태
- 활용: 그냥 AI 챗봇이 아니라 기계 부품 제조 공정 및 품질 관리에 특화된 도메인 맞춤형 에이전트라고 서술하면 전문성이 돋보입니다.

정량적 기대효과 vs 정성적 기대효과
- 뜻: 숫자로 증명하는 성과와 체감되는 가치 변화
- 활용: 기획서 결론부에는 반드시 정량적 수치(업무 시간 70% 단축, 불량 원인 분석 시간 4시간에서 5분으로 단축)와 정성적 가치(현장 초보자의 업무 숙련도 조기 확보)를 나누어 적어야 신뢰성을 얻습니다.

---

5. 비전공자를 위한 실전 제작 팁

- 백엔드와 프론트엔드를 따로 만들지 않고 파이썬 기반의 Streamlit 하나로 통합하여 만듭니다.
- 실제 공장 데이터를 구하기 어렵다면 AI에게 요청하여 가상의 그럴듯한 품질 불량 이력 CSV 데이터를 30~50줄 정도 미리 만들어둡니다.
- 심사위원에게는 설치 파일이 아닌 웹 링크(URL)나 2~3분짜리 화면 시연 녹화 영상을 보여주는 것이 시스템 오류 없이 가장 안전합니다.
