### 1. Agent 목표 (Goal) & 문제 정의
- **해결할 문제:** 글로벌 협력사(중국/한국)에서 수신되는 비정형 출하 성적서(COA/PDF)를 수기로 대조하느라 건당 25분이 소요되고, 도면 공차 휴먼에러로 연간 수억 원대 라인 결함 유입 위험 발생.
- **Agent의 최종 목표:** 다국어(한/영/중) 성적서를 1.2초 내 자동 구조화하고, 사내 도면 한계공차(LSL/USL) 및 ISO 2859-1을 대조하여 **입고 승인서 발급 또는 표준 부적합 통보서(NCR/8D)를 자율 발행**함.

---

### 2. Agent 6요소 구현 아키텍처 (Core Architecture)

```
[입력: PDF 성적서] ➔ [1. Goal: 판정 목표] ➔ [2. Planning: 4단계 작업 분해]
                           │
                           ▼
                 [3. Reasoning: 공차/AQL 추론] ── (Tool Use: OCR / DB / CJK PDF)
                           │
                           ▼
                 [4. Feedback: 오류 보정 / NCR 전환] ── (Memory: 감사로그 / 협력사DB)
                           │
                           ▼
          [출력: 4-포맷 승인서 / 부적합 통보서(8D) 자율 발행]
```

| Agent 핵심 요소 | 구현 기술 및 세부 동작 내용 |
|:---|:---|
| **🎯 Goal (목표 이해)** | 출하 성적서의 규격 일치율 100% 무결점 감사 및 자율 행정 조치 문서 완결 |
| **📋 Planning (작업 계획)** | `다국어 OCR 스트림 파싱` ➔ `사내 도면 DB 공차 매핑` ➔ `ISO 2859-1 한계선 추론` ➔ `행정 공문 빌드` 4단계 자동 파이프라인 수행 |
| **🧠 Reasoning (상황 추론)** | 도면 상하한 공차(LSL/USL) 대조, 단방향 규격 자동 처리, Cpk 공정능력 추론, AQL 결함 허용치 초과 판정 |
| **🛠️ Tool Use (도구 실행)** | `Tool 1: PyMuPDF / Vision API` (문서 파싱), `Tool 2: QC Master DB` (도면 규격 매핑), `Tool 3: Vendor Manager DB` (협력사 실적 동기화), `Tool 4: Doc Generator` (Excel/PDF/HTML/MD 4대 포맷 생성) |
| **💾 Memory / State (상태 기억)** | `audit_history` 검사 이력 저장, `vendors.json` 협력사 누적 검사 건수 및 합격률 영구 동기화 |
| **🔄 Feedback (결과 보정)** | 공차 초과 발견 시 출하 보류(Lock) 발동 및 8D 대책서 요구 워크플로우로 자율 전이 / API 통신 실패 시 100% 로컬 룰베이스 무중단 폴백 |

---

### 3. 신규 개발분 및 기존 자산 명세
- **본 대회 기간 신규 개발분 (100%):**
  1. 한/영/중 3개국어 출하검사 성적서 지능형 파서 및 3단 무중단 폴백 엔진 (`report_parser.py`)
  2. 사내 도면 한계공차 대조 및 단방향 공차 자동 보정 판정기 (`evaluator.py`)
  3. CJK 벡터 폰트 임베딩 4-포맷 입고 승인서 & 표준 NCR 자율 생성기 (`ncr_generator.py`)
  4. 협력업체 등록/수정/품질이력 관리 마스터 관제소 (`vendor_manager.py`)
  5. Streamlit 기반 프리미엄 관제 대시보드 (`main.py`)
